# Буквария

Образовательная **мобильная веб-игра** для развития беглого чтения у детей 7–9 лет (2–3 класс начальной школы). Запускается прямо в браузере смартфона — без установки из сторов, без аккаунтов.

## Идея и ценность

**Проблема.** Беглое чтение — фундамент всей школьной успеваемости, но тренировать его дома скучно: ребёнок читает вслух, родитель слушает «через силу», обратной связи мало, мотивация падает. Цифровые тренажёры обычно сводят чтение к тапам по экрану и не работают с живой речью.

**Решение.** Буквария показывает ребёнку короткий текст и слушает, как он читает его вслух. Игра оценивает чтение по двум метрикам:

- **Точность** — какая доля слов распознана корректно
- **Темп (WPM)** — сравнивается со школьными нормативами техники чтения

Игра обёрнута в нарратив: волшебная страна с 33 буквами-персонажами, кляксный монстр Чернослов накрыл её Покрывалом Молчания, и ребёнок-Голосник своим живым чтением возвращает буквам голос. Контент разбит на 6 регионов по 5–6 букв, регионы открываются последовательно. Финал — боссфайт против Чернослова.

**Почему это круто.**
- **Mobile-first.** Игра проектируется под смартфон в портретной ориентации — то устройство, которое реально есть у ребёнка под рукой. Открыл ссылку — и читаешь, никаких установок и регистраций.
- Тренирует **реальный навык чтения вслух**, а не «нажми на правильную картинку».
- Многосигнальная валидация: даже если детский голос плохо распознаётся ASR-движком, тренажёр опирается также на темп и VAD — ребёнок не получает несправедливое «неправильно».
- Никаких бинарных «правильно/неправильно» — только плавные шкалы и поощрение, что важно для младших школьников.
- Соответствует ограничениям конкурса Учи.ру: **внутри приложения нет ИИ-моделей** — используется только системный ASR браузера/ОС.

## Стек технологий

- **Движок:** Cocos Creator 3.8+
- **Язык:** TypeScript
- **Платформа:** Web, **mobile-first** — основной таргет мобильные браузеры в портретной ориентации, дизайн-разрешение 720×1280. Адаптивная вёрстка корректно работает и на планшете, и в десктопном браузере, но первичный сценарий — смартфон.
- **Speech recognition:** Web Speech API (`SpeechRecognition` / `webkitSpeechRecognition`) — системный ASR браузера/ОС
- **Audio analysis:** Web Audio API (`getUserMedia` + `AnalyserNode`) для VAD
- **Алгоритмы:**
  - Needleman–Wunsch — выравнивание распознанной речи с целевым текстом
  - Расстояние Левенштейна — мягкий матчинг похожих слов
- **Графика:** программный рендер UI через Cocos `Graphics` + растровые иллюстрации регионов

В этом репозитории лежит собранный билд `web-mobile`: `cocos-js/` — рантайм движка, `assets/` — упакованные сцены и ресурсы, `src/` — скомпилированный код игры, `index.html` — точка входа.

## Компоненты системы и их взаимодействие

Приложение **полностью клиентское**, бэкенда нет — весь геймплей и хранение прогресса работают в браузере.

```
┌──────────────────────────────────────────────────────────┐
│                   Браузер (клиент)                       │
│                                                          │
│   ┌────────────────────────────────────────────────┐    │
│   │  UI (Cocos Creator / Graphics)                 │    │
│   │  Home → WorldMap → RegionMap → Reading →       │    │
│   │  Reward → BossFight → Victory                  │    │
│   │  + ParentScreen (кабинет родителя)             │    │
│   └────────────────────────────────────────────────┘    │
│                ▲                                         │
│                │ метрики (точность / WPM)                │
│                │                                         │
│   ┌────────────┴────────────────────┐                   │
│   │  Логика чтения                  │                   │
│   │  • WordAligner (NW + Левенштейн)│                   │
│   │  • BossFightController          │                   │
│   │  • SegmentRevealer / Pulse / …  │                   │
│   └────────┬─────────────┬──────────┘                   │
│            │             │                              │
│   ┌────────▼─────┐  ┌────▼───────────────┐  ┌────────┐ │
│   │ SpeechService│  │ AudioMonitorService│  │GameState│ │
│   └────────┬─────┘  └────┬───────────────┘  │+Storage│ │
│            │             │                  └───┬────┘ │
└────────────┼─────────────┼──────────────────────┼──────┘
             │             │                      │
             ▼             ▼                      ▼
   Web Speech API     Web Audio API         localStorage
   (системный ASR)    (микрофон, VAD)       (прогресс)
```

- **UI-слой** — экраны (`HomeScreen`, `WorldMapScreen`, `RegionMapScreen`, `ReadingScreen`, `RewardScreen`, `BossFightScreen`, `VictoryScreen`, `ParentScreen`) собираются программно из `Graphics`-примитивов и токенов дизайна. Навигация — через `ScreenManager`.
- **Сервисы** — обёртки над браузерными API: `SpeechService` (Web Speech API с auto-restart), `AudioMonitorService` (Web Audio API: VAD), `Viewport` (singleton размеров и safe-area).
- **Логика** — чистые модули без зависимости от Cocos: `WordAligner`, `BossFightController`, `SegmentRevealer`, `MultiTargetMatcher` и др. Покрыты юнит-тестами.
- **Данные** — `GameState` (прогресс, валюта, история попыток) с персистенсом в `localStorage` через `ProgressStorage`; `LetterData` (контент букв и регионов).

**Внешние взаимодействия:** только браузерные API (микрофон через `getUserMedia`, ASR через Web Speech, хранение прогресса через `localStorage`). Сетевые запросы и серверные компоненты отсутствуют — игра работает офлайн после загрузки.

### Кабинет родителя

Отдельный экран `ParentScreen` для взрослого, который хочет увидеть, как идут дела у ребёнка. Доступен с главного экрана.

- **Math gate.** Перед входом — небольшая задачка на сложение/вычитание/умножение с четырьмя вариантами ответа. Это защита от того, чтобы ребёнок случайно зашёл в кабинет и нажал «Сбросить прогресс». Прохождение шлюза не персистится — при повторном входе нужно решить новую задачу.
- **Список регионов.** Раскрывающиеся карточки с шестью регионами; внутри каждого — буквы и для каждой буквы история попыток (точность, темп, дата, сколько ушло времени, какие игровые механики были активны в этом регионе — кляксы, маяк, таймер замка).
- **Сброс прогресса.** Кнопка для полного обнуления — на случай, если родитель хочет передать игру другому ребёнку или начать заново.

Кабинет ничего не отправляет наружу: всё считывается из того же `localStorage`, в который пишет геймплей.

## Как запустить проект

Это собранный статический билд — нужен любой HTTP-сервер. Открывать `index.html` напрямую через `file://` **нельзя** (Cocos и Web Speech API требуют HTTP/HTTPS-контекст). Для микрофона нужен **HTTPS или localhost** — иначе браузер не выдаст разрешение на `getUserMedia`.

В папке с этим README:

```bash
npx serve .
```

Открыть `http://localhost:3000` в Chrome/Safari/Edge. Игра проектируется под смартфон, поэтому при просмотре на десктопе **обязательно переключите DevTools в режим мобильного устройства** (iPhone / Android) — иначе соотношение сторон будет неверным и часть UI рассчитана не на ту ширину.

### Поддержка браузеров

- Целевые платформы: **Chrome на Android** и **Safari на iOS** (iOS 14.5+).
- На десктопе работает Chrome / Edge — но только как preview-режим для разработки.
- В Firefox распознавание речи не работает — игра запустится, но геймплей чтения будет недоступен.
- Только portrait-ориентация.
